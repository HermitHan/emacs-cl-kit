# 在已有 Emacs 的 Linux 设备上试用

不要把 Mac 里的整个 `~/.emacs.d/` 复制到 Linux。这样会把平台相关的包、输入历史和 OAuth 授权一同带过去，还可能覆盖原先的 LispWorks 入口。

1. 在目标机器的终端确认 `emacs --version` 至少为 29.1，并用 `command -v my-lispworks` 核对要使用的控制台程序。首次在线安装需要 curl 和网络。自己的离线设备也可使用私用版 `emacs-portable-offline.sh` 和对应校验文件。
2. 先安装到新的目标目录。GitHub Release 发布后，在有 `my-lispworks` 的 Linux 机器上直接运行下面两条命令。

   ```sh
   curl -fsSL https://github.com/HermitHan/emacs-cl-kit/releases/latest/download/emacs-portable-source.sh | bash -s -- --target "$HOME/.emacs-portable-trial" --backend my-lispworks --non-interactive
   emacs --init-directory "$HOME/.emacs-portable-trial" -nw
   ```
3. 用 `M-x slime` 启动选定实现，在 REPL 求值 `(lisp-implementation-type)`。用 `M-x han/slime-start` 选 SBCL，验证两个 REPL 能同时存在。REPL 中 `M-RET` 提交表达式。`C-c r` 是源码 rewrite，`C-c C-r` 是 SLIME 对选区求值。
4. 如需 gptel，在这个新的配置目录里重新授权。在 SSH 终端可以通过另有浏览器的设备完成 device 登录。多个独立配置目录各自保管授权。
5. 试用满意后可以继续用这个启动命令，原设置不会受到影响。若要替换原来 `~/.emacs.d/` 的正式配置，先正常退出相应 Emacs 并自行完整备份，再用上面的同一个 URL，将管道右侧改为 `bash -s -- --adopt --dry-run`，预览默认目录的改动。安装器会保留自有文件、包目录与机器状态；若旧版本 ELPA 没有满足核心依赖，会拒绝接管。此时继续使用试用目录即可。

如果目标机只提供低于 Emacs 29.1 的系统包，须先准备新版 Emacs 并通过 `EMACS=/绝对路径/emacs` 告诉安装器用哪个版本。无需安装 LispWorks 才能使用 SBCL；同样，如果你只装有 LispWorks 控制台，也可只选择它。
