# Emacs CL Kit 使用手册

[返回首页](../README.zh-CN.md) · [English handbook](handbook.en.md)

如果你已经在 REPL 里得到了 `(add-two 40)` 的结果，可以接着试下面的练习。平时查键位时，先看光标在哪个 buffer 里。同一个回车键，在源码里换行，在聊天和 REPL 里各有自己的提交方式。

## 熟悉 Emacs 的操作方式

**用分屏同时看源码和 REPL。** 在 `cl-kit-demo.lisp` 中按 `C-x 3` 左右分屏。光标会移到新窗；如果那里没有显示已启动的 REPL，按 `C-x b`，输入 `*slime-repl` 并选中对应的 buffer。用 `M-o` 在两边往返。多个分屏可以显示同一个 buffer，修改会同时出现在两边。想专心看一边时按 `C-x 1`，之后仍可用 `C-x b` 找回另一个 buffer。

**弄清一个键做什么。** 在 REPL 里按 `C-h k`，再按 `M-RET`，帮助页会显示 `slime-repl-return`。换到源码 buffer 按 `C-h m`，可以看到当前的主模式（如 Lisp）和次模式（如 SLIME、Paredit）。终端截走 `C-SPC` 时，用 `M-x set-mark-command` 设置标记，再移动光标选取文本。要按 GNU 教程练习默认键位，可在另一个终端运行 `emacs -Q -nw`，按 `C-h t`。

**试一次只影响当前 buffer 的设置。** 用 `C-x C-f` 打开一个练习用的文本文件，按 `M-:`，输入 `(setq-local fill-column 88)` 并回车。用 `C-h v fill-column RET` 看它的局部值，再用 `M-:` 执行 `(kill-local-variable 'fill-column)` 恢复默认。`fill-column` 控制填充段落时的目标宽度。这里执行的是 Emacs Lisp。还可在 `*scratch*` 里粘贴 `(length '(a b c))`，把光标放在最后一个右括号之后，按 `C-x C-e`，屏幕底部应显示 `3`。两个练习都由 Emacs 自己求值。

## 在运行中的 Lisp 里继续实验

保留首页练习里的 `add-two` 定义。在 REPL 输入下面一行，按 `M-RET`，结果应为 `(0 2 42)`。

```common-lisp
(mapcar #'add-two '(-2 0 40))
```

`#'add-two` 把函数交给 `mapcar`，它将函数依次用于列表中的元素并收集结果。要在自己的程序里重复这个操作，可以在同一个源码文件中再加一个定义。

```common-lisp
(defun add-two-to-each (numbers)
  (mapcar #'add-two numbers))
```

保存后按 `C-c C-k` 编译并加载整个文件。在 REPL 分别试 `(add-two-to-each '(-2 0 40))` 和 `(add-two-to-each '())`。前者得到同样的三个数，后者得到空列表 `NIL`。只想对源码里选中的表达式求值时，按 `C-c C-r`。

**同时比较 SBCL 和 LispWorks。** 先用 `M-x slime` 启动默认实现，再用 `M-x han/slime-start` 选择另一个。两个 REPL 各自执行 `(lisp-implementation-type)`，便能确认当前实现。在 `M-x slime-list-connections` 列表中，把光标移到目标连接，按 `d` 设为默认，再回到未绑定特定连接的源文件编译。每个进程都需要编译一次 `add-two` 才有这个定义。

**设置下次启动的实现。** 安装器把选择保存在安装目录的 `var/slime-default-lisp`。要更换它，再次运行安装管道，将右侧写成 `bash -s -- --backend 名称`；原来指定过 `--target` 的也要带上同一目录。只想临时换一次，可以这样启动试用环境：

```sh
SLIME_DEFAULT_LISP=sbcl emacs --init-directory "$HOME/.emacs-portable-trial" -nw
```

Emacs 依次尝试本次环境变量、保存的选择、SBCL、首个可用实现。如果 LispWorks 控制台映像不在 `PATH`，启动安装器和 Emacs 前，都要把 `LISPWORKS` 设为映像的完整可执行路径。已有服务器的例子见[迁移指南](迁移到已有设备.md)。

## 让 gptel 看见相关代码

**给聊天补充上下文。** 如果问题涉及另一个文件，切到那个 buffer，选中相关定义，执行 `M-x gptel-add`。回到聊天，在 `M-x gptel-menu` 核对加入的内容，再用 `C-c RET` 发送。换项目时可以从菜单移除已经用完的上下文。在没有桌面浏览器的 SSH 会话，可用 `M-:` 执行 `(gptel-openai-oauth-login nil 'device)`，按提示在另一台设备上授权。

聊天中，`C-c j b` 到当前消息的正文开头，`C-c j p` 和 `C-c j n` 到上一条和下一条。`C-c j u` 找当前或最近的用户消息，`C-c j a` 找 GPT 消息；已在对应消息开头时，再按一次会到该角色的上一条消息。

**在接受前测试一次改写。** 例如，选中整个 `add-two` 的定义，用 `C-c r` 要求补一个文档字符串。生成后在 Diff 窗口操作：

| 你想做什么 | 在 Diff 中按 |
| --- | --- |
| 把候选函数拿到 REPL 运行 | `y` 复制纯文本候选。到 REPL 用 `C-y` 粘贴、`M-RET` 提交，再测试 `(add-two 40)`。`Y` 复制最初的原文。 |
| 保留候选，进一步修改 | `r` 输入补充要求，例如“把文档字符串缩成一句”。下一次请求携带当前候选及先前的改写要求。 |
| 在聊天里讨论这次修改 | `e` 将原文、候选和要求带进聊天草稿，可编辑后再发送。独立发起的改写有自己的上下文。 |
| 决定是否采用 | `a` 将候选写入源码 buffer，再用 `C-x C-s` 保存。`k` 放弃候选。 |
| 暂时离开审阅 | `s` 回源码；`q` 关闭 Diff 窗口并保留候选；`?` 查看按键帮助。 |

REPL 中提交候选函数后，这个 Lisp 进程已经在使用新定义。此时若在 Diff 按 `k` 放弃改写，回到原函数再按 `C-c C-c`，即可让 REPL 恢复原行为。这个测试方法适合完整函数；单独复制函数体内的几行，可能会缺少局部变量。

**把偏好留给下次请求。** `M-x han/gptel-edit-preferences` 打开安装目录里的 `gptel-preferences.md`。例如写入“遍历列表时优先考虑 `mapcar` 或 `dolist`”，`C-x C-s` 保存后，下次聊天和改写都会读取。默认回复跟随提问语言，只有代码、难以判断时才参考系统语言。若想固定中文，运行 `M-x customize-option RET han/gptel-response-language RET`，选 `Preferred language`、填入 `中文`，再选 `Apply and Save`。单次请求仍可明确指定语言。

## 修改、更新和恢复配置

| 想改哪里 | 从哪里开始 |
| --- | --- |
| 全局按键与模块加载顺序 | 安装目录的 `early-init.el` 管启动初期，`init.el` 加载各模块并定义个人键位。[键位定义](../payload/init.el) · [逐模块阅读指南](../payload/配置阅读指南.org) |
| 只保存这台机器的选项 | 用 `M-x customize-option` 修改变量并选 `Apply and Save`。Customize 写入本机 `custom.el`；用 `M-: user-emacs-directory RET` 查看所在目录。 |
| 让自己的改动跟着设备走 | 仓库的 `payload/` 是安装模板。要维护自己的版本，把改动保存在自己的模板中。安装目录里的 `var/` 存历史等运行状态，gptel 授权保存在本机 `.cache/gptel-openai/`。[状态目录设置](../payload/lisp/init-state.el) |

从任意目录重跑安装命令，指定**上次安装的目标目录**即可更新。在管道右侧用 `bash -s -- --dry-run` 可预览默认目录；试用目录还要带上原来的 `--target`。遇到本机改过或删过的受管文件，先比较安装器列出的路径。确实要接管已有配置时，先关闭对应 Emacs、在目录外完整备份，再用 `--adopt --dry-run` 查看要接管的文件。源码旁的旧 `.elc` 可能优先于新源码加载，需先备份并移走安装器指出的文件。

有变更的安装会在目标旁创建 `<目标名>.portable-backups/`。终端会打印这次操作的恢复命令；管道安装后，这条命令使用备份里的本地程序，断网也能还原。恢复会核对受管文件的内容和权限，已安装的包、历史和其他文件另行保管。[依赖与离线安装](依赖与离线包.md)

**先核对下载的安装器。** 从同一 Release 下载 `emacs-portable-source.sh` 和同名的 `.sha256` 文件。在它们所在的目录，macOS 运行 `shasum -a 256 -c emacs-portable-source.sh.sha256`，Linux 运行 `sha256sum -c emacs-portable-source.sh.sha256`。结果为 `OK` 后，运行 `bash ./emacs-portable-source.sh`，也可以追加原来的 `--target`。

**自己维护发行包。** 在仓库根目录运行 `python3 scripts/make-release.py --output dist`，会生成单文件安装器、源码归档及各自的 SHA-256 校验文件。要把日常配置中的改动带回仓库，可以用 `scripts/export-config.py` 导出到新目录，再与 `payload/` 比较。[配置文件清单](../scripts/config-files.txt) · [发行文件清单](../scripts/release-files.txt)

## 遇到问题时

| 现象 | 先检查什么 |
| --- | --- |
| 启动后快捷键像另一套配置 | 按 `M-:`，执行 `user-init-file`，核对实际路径。用首页对应的 `--init-directory` 命令重开试用目录。启动报错时查看 `*Messages*`，或在启动命令里加 `--debug-init`。 |
| SLIME 找不到 Lisp | 在 Emacs 用 `M-:` 执行 `(executable-find "sbcl")`。SSH 里应检查远端的可执行文件；LispWorks 需可运行的控制台映像。 |
| REPL 只换行，或报告函数未定义 | `M-RET` 提交；终端截键时可用 `M-x slime-repl-return`。在目标 REPL 检查当前包和实现，回到源码给该连接重新编译定义。 |
| 改写要求选区，或聊天看不到别的文件 | 源码中先设置标记、选中完整函数，再按 `C-c r`。聊天要引用其他 buffer 时，在那个 buffer 里选区并 `M-x gptel-add`。 |
| gptel 登录了但收不到回复 | 在同一安装目录打开聊天，检查网络、`curl`、聊天状态和 `*Messages*`。需要重新授权时运行 `M-x gptel-openai-oauth-login`。 |
| 安装报下载超时或哈希错误 | 看错误指出的是安装器还是依赖。安装器的备用地址见对应版本发布说明；依赖下载失败可在网络恢复后重跑。自备离线包须与该版本的固定哈希匹配。[发布说明](https://github.com/HermitHan/emacs-cl-kit/releases) |

## 接着读什么

- **熟悉编辑器**　先做 `C-h t` 的移动、选择和帮助练习，再读 Emacs 手册的 Buffers 和 Windows 章节。离线时可用 `C-h i` 打开本机 Info 手册。[GNU Emacs Manual](https://www.gnu.org/software/emacs/manual/html_node/emacs/)
- **读懂配置**　从 Emacs Lisp 的列表、求值、`defun` 开始。打开一个 `lisp/init-*.el` 文件，用 `C-h f` 查其中的 `require` 或 `add-hook`。[An Introduction to Programming in Emacs Lisp](https://www.gnu.org/software/lispintro/)
- **学习 Common Lisp**　跟着《Practical Common Lisp》第 2、3 章，从 REPL 走到一个小型数据库。查参数和返回值时，在 Lisp 源文件的标准符号上按 `C-c l` 打开 HyperSpec。[Practical Common Lisp](https://gigamonkeys.com/book/) · [Common Lisp HyperSpec](https://www.lispworks.com/documentation/HyperSpec/Front/index.htm)
- **深入交互开发**　想理解编译、REPL 和调试器，读 SLIME 手册；想了解选区、上下文与改写，读 gptel 的用法示例。本配置的定制键位可在相应 buffer 用 `C-h k` 核对。[SLIME User Manual](https://slime.common-lisp.dev/doc/html/) · [gptel](https://github.com/karthink/gptel)
